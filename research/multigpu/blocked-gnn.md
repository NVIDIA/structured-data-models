# Destination-blocked relational GNN prototype

`blocked_gnn.py` is a research-only adapter for the existing KumoRelational `InvariantGNN`. It addresses the measured 6.10 GiB five-statistic allocation on the H&M C=65,536 context graph without modifying checkpoint weights, graph sampling, features, or SDM core code. It is not another distributed execution framework. CUDA numerical screening below found significant checkpoint-dependent failures; this is not an accepted parity-preserving optimization.

## Preserved computation

For each hop, compute the original full `src_lin(x)` and `skip_lin(x)`. Partition destination rows into contiguous blocks; each block invokes the existing reducer and immediately executes the original `torch.addmm(skip, stats.flatten(1), aggregation_lin.weight.T)`. Release the block statistics before computing the next block. Readout indexing on the final hop, then layer normalization/GELU, and the final output projection/normalization stay in their original order.

The reducer remains responsible for `[sum, mean, std, min, max]`, including population variance, the `variance <= 1e-5` zero-standard-deviation rule, empty segments, infinities, NaNs, duplicate edges, and original edge ordering. Reduced statistics are cast back to the source dtype before projection, exactly as in the current implementation. `src_lin` bias is included once per incoming message; `skip_lin` bias once per destination; the checkpoint's aggregation projection has no bias. No partial-statistic merge or reassociation is introduced. The same edge-type random generator and cache recording/reuse behavior are preserved.

On CUDA, absolute CSR offset slices address the original global source-index and edge-type arrays. No scalar GPU readback or edge-array partition is needed. The adapter explicitly requires the existing Triton reducer for supported source dtypes and raises when it is unavailable; it does not silently select the eager path that could materialize all edge messages. On CPU, each block slices its edge span and rebases offsets before calling the existing eager reducer. The CPU path may still materialize all messages for a high-degree destination.

## Memory bound and limits

For N nodes, D channels, block size B, and s bytes per statistics element, the statistics allocation changes from `5*N*D*s` to at most `5*min(B,N)*D*s`. On the measured 1,279,607-node H&M graph with D=512 and BF16, this buffer alone is approximately 6.102 GiB natively versus 0.078125 GiB at B=16,384 (80 MiB). These are shape-derived allocations, **not measured GPU peak savings**.

The measured capacity workload `results/relational/workload-hm-c65536-b512/workload.json` uses seed 1729 and 4,096 queries: article 571,241 + customer 65,536 + transactions 642,830 = 1,279,607 nodes. Reconstructing `HomogeneousGraph.from_tables` directly from that workload's saved `graphs.pt` confirmed 2,571,320 directed edges and four edge types. The earlier CPU sizing workload `cpu-profiles/rel-hm-c65536-q256/workload.json` uses seed 20261008 and 256 queries: article 571,256 + the same customer/transaction counts = 1,279,622 nodes. Both artifact paths are beneath `.kumo-multigpu-20261008/`. They are different sampled workloads, not contradictory counts for one graph; this prototype's capacity estimate uses the actual GPU workload.

Full node states, transformed source states, skip/output states, graph indices, row-encoder buffers, ICL caches, and GEMM workspace remain resident. Overall memory is still O(ND + E); the adapter only bounds the five-statistic workspace and avoids the full projected-output-plus-skip overlap by writing back into the skip buffer. CUDA latency may worsen from multiple reducer/GEMM launches and smaller GEMMs. Small block GEMMs may produce different floating-point rounding; semantic preservation is not a bitwise-parity promise.

In particular, the blocked path retains the full transformed source matrix until every destination block has been reduced, while the native one-shot reduction can release it before the full statistics projection. The net peak reduction is therefore not simply the difference between the two statistics-buffer sizes; tensor lifetimes and overlapping allocations must be measured in the actual model.

The adapter shares the supplied module's parameter objects. Install it only after loading a checkpoint and before fit, for example `install_blocked_gnn(model.models[task], block_size=16384)`. It rejects gradient-enabled execution and nonpositive block sizes. The nested research wrapper changes state-dict names; do not serialize it as a replacement checkpoint format. It is not claimed to support compilation, training, or a non-Triton CUDA backend.

## Numerical gates and local validation

Before running tests, the module-output gates were declared as FP32 `rtol=1e-5, atol=2e-6` and CPU BF16 `rtol=0.02, atol=0.02`; statistic tensors require bitwise equality, allowing matching NaNs. Gates were not relaxed after testing. Tests compare the actual existing `InvariantGNN` module, not a substitute mathematical model, with matched edge-type seeds and both fresh and frozen-cache calls. Coverage includes hops 0–3, readout subsets with duplicate/reordered indices, block sizes 1/3/larger-than-graph, zero-degree and all-empty graphs, repeated/mixed-type edges, constant inputs, infinities/NaNs, and FP32 parameters under BF16 autocast.

An initial draft also blocked `skip_lin`; one random three-hop FP32 comparison exceeded the strict gate (maximum absolute difference 1.32e-5). That extra change was removed: the final implementation computes the native full skip projection. This reduces the numerical changes but is not proof that every graph/checkpoint is within tolerance.

The final local module suite passed 95 cases on CPU (PyTorch 2.9.1, Python 3.12.14), including observed statistics shapes never exceeding B destinations. This checks tensor shape, not the allocator's actual peak. An independent review against current classifier and regressor checkpoint GNN weights found an important limitation: FP32 singleton blocks failed the unchanged strict module-output gate; B=17 and B=256 passed, and BF16/BF16-autocast passed all three sizes. The regression singleton comparison included a violating absolute error of 7.03e-6. Statistics remained bitwise equal, so destination-sized projection GEMM rounding is the leading explanation, not a proven universal diagnosis. Singleton blocks do **not** qualify under the declared FP32 gate; the implementation is a prototype, not an accepted parity-preserving optimization for all configurations. CUDA/current-task output validation remains required.

The completed independent screen ran 31 cases: 29 passed and the two FP32 singleton checkpoint configurations failed. N=257 with B=64 and B=128 passed all tested precisions for both classifier/regressor checkpoint GNNs, on fit and frozen-cache query calls, establishing actual multi-block coverage. The failed classifier singleton arm had maximum fit/query errors 1.263618e-5/1.66893e-5. Per-arm source/checkpoint identities and error JSON are retained in `.kumo-multigpu-20261008/blocked-gnn-cpu-review`; review commit `7f5251f56` retains the failing gates rather than marking them accepted. These remain CPU GNN-module results, not full-task predictions.

Run `PYTHONPATH=. python -m pytest test/research/test_blocked_gnn.py`. Before deployment, measure the unmodified and blocked checkpoint on identical H&M context/query graphs, starting with FP32 and then the production BF16-autocast path. Check individual statistics, final predictions and task quality, fit/predict time, per-device allocated/reserved peaks, allocator settings, and a block-size sweep. Repeat the failed C64k E8 resident fit plus the native CPU-offload control; compare against stage placement under the same allocator. Full-task runs remain experimental when a module-level gate fails; task metrics cannot silently override that failure.

## CUDA numerical screen on the replacement L4 host

Source `b721583a9` was tested on the replacement Frankfurt four-L4 host, using one GPU, PyTorch 2.9.1+cu130, with TF32 disabled. The first suite passed 57/57 cases in 3.05 seconds: 45 exact statistic comparisons at D=33 (FP32/BF16/FP16, nonfinite/empty/reordered graphs, N=257, B=1/64/128) and 12 D=32 GNN comparisons covering every node plus duplicate readouts, fresh/frozen caches, default/nondefault streams, and FP32/BF16/autocast. These are correctness test durations, not inference-performance measurements.

The stronger D=512 actual-checkpoint screen then collected 31 tests: one CPU threshold test passed, seven CUDA checkpoint configurations passed, and **23 CUDA checkpoint configurations failed** the original gates. All six N=64/B=256 single-block controls were bitwise equal; the other passing configuration was the N=64/B=17 FP32 regressor. Every N=257 multi-block case failed, including BF16 and BF16 autocast, despite the smaller synthetic GNN suite passing.

B=64 and B=128 produced the same recorded error values for these fixtures. A separate first-hop D=512 classifier probe used identical transformed-source and skip tensors for both projections. The full and blocked statistics were bitwise identical in FP32 and BF16 autocast. The projection itself differed: FP32 maximum/mean error 0.0000472069/0.00000172466, BF16-autocast maximum/mean 0.125/0.00348989. This directly locates a numerical change at the block-sized `addmm`; source review found no changed edge indexing, aggregation semantics, cache randomness, or hop ordering. Later amplification through nonlinearities or variance-threshold crossings is plausible but was not isolated by this first-hop probe. No tolerance was relaxed and no failed configuration was promoted as exact.

Evidence is retained under `.kumo-multigpu-20261008/blocked-gnn-gpu-review/`: `blocked-gnn-lowlevel-b721583a9-v1` and `blocked-gnn-checkpoint-b721583a9-v1` contain timestamped bounded-process receipts, complete stdout and JUnit XML; the latter has all 30 per-configuration checkpoint/source hashes and fit/query error JSONs. `blocked-gnn-projection-probe-b721583a9-v1` preserves the exact stdin script, captured result JSON lines, and provenance. Independent audit reconciled all checkpoint records against XML and retained all failures; it did not independently recompute tensor errors because full hidden arrays were not saved. The low-level and checkpoint jobs ran at 02:05:43–02:05:49 and 02:06:33–02:06:41 UTC on 2026-10-08. Their compilation warms the shared Triton disk cache before subsequent full-model fits, which must therefore not be called cold-compilation measurements.

## Remaining capacity failure and one unimplemented next step

The final resident single-GPU H&M C=65,536/E=8 retry used source `ae4e5e549` and `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`, with effective allocator settings verified after a CUDA allocation in the same process that ran the benchmark. Both the unblocked baseline and B=16,384 prototype still failed. The baseline reached a 1.22 GiB skip-projection allocation failure; the blocked model advanced past the five-statistic allocation but failed inside `block.norm(x)` at `blocked_gnn.py:123`, requesting 2.44 GiB with 2.19 GiB free. At that allocation failure the traceback reported 19.43 GiB allocated and only 157.92 MiB reserved but unused. The runner's separately captured current allocation is lower because it was sampled after exception unwinding; these two measurements must not be conflated.

The exact failure records and provenance are `.kumo-multigpu-20261008/results/relational-resume/relational-resume-l4-hm-c65536-e8-ensemble1-gnn{0,16384}-expandable-verified/{failure.json,provenance.json}`. These verified retries are distinct from earlier replacement-host attempts that set `PYTORCH_ALLOC_CONF`: a fresh-process CUDA allocation plus allocator snapshot showed that spelling was ignored by this runtime, so those earlier arms used the default allocator despite the environment string. No inference-quality result exists for either failed resident retry.

A concrete next step is to stream normalization and GELU over destination blocks on **nonfinal** hops. Keep the full `src_lin(x)` and `skip_lin(x)` calls unchanged, immediately apply the existing norm/GELU to each projected block, and retain the normalized full node state required by the next hop. Preserve the current final-hop ordering exactly: select the readout rows before normalization. All destinations still see the complete, unchanged source matrix for that hop; writes go to newly computed buffers, never the caller's input. Drop obsolete local aliases when their last use ends.

The dtype constraint is essential: under the measured CUDA BF16-autocast path, normalization promotes to FP32, while the skip/projection buffer is BF16. Storing normalized values back into that BF16 buffer would silently change the model. A safe prototype would allocate next-hop storage with the first normalized block's actual dtype and only reuse the skip buffer when its dtype matches. This still requires a full FP32 next-hop state, plus the full transformed source and skip buffers until all blocks finish.

For this 1,279,607-node, D=512 graph, one full FP32 state is 2.4407 GiB and one BF16 state is 1.2203 GiB; an FP32 B=16,384 block is 32 MiB. A simplified live-workspace estimate compares a BF16 projected state plus two full FP32 normalization/activation temporaries (about 6.1016 GiB) with BF16 source and skip states plus one FP32 next-hop state (about 4.8813 GiB), plus block-local temporaries. This suggests roughly **1.1 GiB of possible transient headroom**, not a measured bound on total peak or a guarantee that E=8 will fit. Caller-owned inputs, accumulated ICL caches, allocator behavior, reduction statistics, and backend workspaces still matter; the failing 2.44 GiB allocation is not itself the predicted saving.

This follow-up was deliberately **not implemented or GPU-tested**. It should first be compared against the current blocked path to isolate any new norm/GELU differences, then against the native checkpoint and fixed full-task predictions under the original gates. Existing projection-induced failures must remain visible. The measured frozen source was not changed to pursue an unbounded sequence of capacity variants.
