# TimesFM-3 porting notes

This file records intentional differences between SDM's TimesFM-3 implementation and the [Google Research implementation](https://github.com/google-research/timesfm/tree/e31dadd84cb26bd5153fde6687502b8312e918fb/src/timesfm3/torch). The initial port targets upstream commit `e31dadd84cb26bd5153fde6687502b8312e918fb`. Update the commit and review every entry below when synchronizing with a newer upstream revision.

The source map covers components that have been ported. Add a row and document any adaptation when another component is implemented.

## Repository-wide adaptations

- SDM uses absolute imports and its repository-wide formatting, typing, docstring, copyright, and SPDX conventions.
- Modules accept PyTorch `device` and `dtype` arguments where SDM needs construction directly on the target device, including the meta device used for checkpoint loading.
- Tests assert public numerical and tensor behavior on CPU and CUDA where available. They may differ structurally from upstream tests.

## Configuration and normalization

- [`configs.py`](configs.py) preserves the upstream TimesFM-3 configuration fields, defaults, type annotations, and frozen dataclasses; only repository formatting and documentation differ.
- [`PerDimScale`](normalization.py#L30) accepts `device` and `dtype` so its parameter can be created directly on the target device and with the target dtype.

## Utilities

- [`DecodeCache.init_decode_cache`](util.py#L61) accepts `dtype` so key/value storage can match model precision at allocation time.
- [`DecodeCache.append`](util.py#L127) updates heterogeneous insertion positions with tensor indexing. This replaces [upstream's per-sequence Python loop and `.item()` synchronization](https://github.com/google-research/timesfm/blob/e31dadd84cb26bd5153fde6687502b8312e918fb/src/timesfm3/torch/transformer.py#L296-L314) while preserving its in-place storage and returned cursor semantics.
- The decode cache also records patch masks and optional segment IDs so cached attention preserves the full-sequence masking contract. Its `filled` prefix length avoids attending over unused preallocated capacity without synchronizing CUDA tensors to the host.
- When no initial statistics are supplied, [`get_running_stats`](util.py#L278) creates them on the input device in `float32`. The resulting statistics remain in `float32`, including for lower-precision inputs.
- [`revin`](util.py#L364) checks that `mu` and `sigma` have identical shapes because unequal broadcastable shapes could otherwise silently apply incorrect normalization statistics.
- [`get_output_patch_via_roll`](util.py#L416) uses tensor indexing instead of repeatedly calling `torch.roll`, avoiding intermediate full-tensor allocations while preserving upstream output and wrap-mask semantics.
- Segment IDs remain supported by [`get_running_stats`](util.py#L278) even though the standard TimesFM-3 inference path does not supply them. They preserve the upstream utility contract for independently normalized packed sequences.

## Contiguous Patch Masking (CPM) RevIN refinement

- [`cpm_iterative_revin_refine`](cpm_revin_refine.py#L24) preserves Google’s sequential patch refinement and per-batch block-offset behavior. Per-patch roll selection uses direct `gather` instead of upstream’s one-hot tensor and `einsum`, removing an allocation and reduction while preserving identical selected values. [`update_running_stats`](util.py#L219) preserves Google’s multiplication order so iterative refinement does not accumulate avoidable floating-point differences.

## Dense layers

- [`ResidualBlock`](dense.py#L27) preserves upstream's deferred input-dimension setup. Placeholder modules are registered at construction, and [`set_input_dims`](dense.py#L84) replaces them once while preserving their current device and dtype.
- The integrated TimesFM-3 model must reproduce [upstream model initialization](https://github.com/google-research/timesfm/blob/e31dadd84cb26bd5153fde6687502b8312e918fb/src/timesfm3/torch/model.py#L146-L149) by calling `set_input_dims(2 * (input_patch_len + output_patch_len))` immediately after constructing the pre-transformer residual block and before checkpoint loading, optimizer construction, distributed wrapping, or compilation. First-forward inference remains available for parity with the standalone upstream block but is not the integrated model lifecycle.
- SDM's [`set_input_dims`](dense.py#L84) constructs replacement layers directly on the placeholder's device and dtype rather than constructing them on CPU and subsequently calling `.to(...)`.
- The upstream `dropout` configuration remains unused by the inference-only residual block.

## Transformer layers

- [`make_attn_mask`](transformer.py#L33) and [`make_segment_mask`](transformer.py#L75) preserve upstream mask semantics. In particular, a non-causal attention mask has broadcastable shape `[B, 1, 1, K]` rather than materializing the query dimension.
- [`RotaryPositionalEmbedding`](transformer.py#L87) keeps its non-persistent timescale buffer in `float32`, matching upstream checkpoint behavior and preserving frequency precision. Its sine and cosine tensors are cast to the input dtype before rotation so BF16 and FP16 attention retain one dtype.
- [`MultiHeadAttention`](transformer.py#L178) rematerializes the non-persistent RoPE buffer after state-dict loading. This makes SDM's standard `device="meta"` plus `load_state_dict(assign=True)` path safe without adding checkpoint keys.
- Cached attention preserves patch masks and segment isolation, unlike the pinned upstream cached branch, and restricts keys and values to the populated cache prefix. Cache mutation is explicitly inference-only because an in-place multi-step cache cannot preserve autograd history. Full-sequence attention remains numerically identical to the pinned implementation.
- SDPA receives the broadcastable one-head mask directly instead of explicitly expanding it across heads. The manual path uses a dtype-safe masked softmax and returns zero for fully masked rows, matching SDPA behavior for FP16, BF16, and FP32.
- SDM's generic attention modules use fused QKV parameterization and different scaling/cache contracts. The TimesFM-specific implementation remains local to preserve Google's checkpoint names, QK/V normalization, per-dimension scaling, and attention semantics.

## Pretrained checkpoint loading

- [`TimesFM3`](model.py#L67) pins both configuration and weights to Hugging Face revision `43046b85ec22d584a13f8098c2ed39c889e129c2`, so the architecture and state dictionary cannot independently drift.
- The downloaded configuration constructs [`_TimesFM3`](model.py#L368) on the meta device before [`TimesFM3._load_from_pretrained`](model.py#L164) materializes the safetensors checkpoint directly on the requested device with strict, assigning state-dict loading. This avoids allocating a second full model while rejecting missing or unexpected checkpoint keys.
- The non-commercial license prompt gates the weights download. The small configuration file is fetched first without a prompt because it does not grant access to or materialize the licensed weights.

## Public SDM adapter and recipe

- [`TimesFM3._forward`](model.py#L241) maps SDM's ordered table rows to Google's decode boundary: target columns become target variates, feature columns present in the query become past-and-future covariates, and context feature columns omitted from the query become past-only covariates. [`expand_query`](model.py#L1074) restores the context schema with dummy values before normal recipe execution while the original query schema retains the covariate roles.
- The adapter flattens arbitrary leading batch dimensions only at the Google boundary, transposes row-major SDM tables to variate-major series, masks non-finite values, calls [`_TimesFM3.decode`](model.py#L713), selects target forecasts, and restores SDM's leading dimensions. Output columns are target-major quantiles such as `target__q10` through `target__q90`.
- `fit` caches owned copies of only the processed context feature and target tensors; `predict` reuses them and performs the same single-pass decode as `forward`. It does not build a transformer key/value cache because TimesFM-3's non-autoregressive decode jointly constructs and processes the complete context and forecast horizon.
- [`default_recipe`](recipe.py#L7) intentionally leaves features and targets unchanged because TimesFM-3 owns missing-value masking, RevIN normalization, clipping, detrending, and quantile generation. It only averages estimator outputs. A global `SortQuantiles` step is not valid for flattened multi-target output because it would also reorder values across different targets.
- Custom recipes with a non-identity target pipeline are rejected because the generic recipe lifecycle cannot invert target transformations over TimesFM-3's flattened target-by-quantile columns. A future recipe-level grouped-output contract could reshape predictions by target and quantile, inverse-transform each quantile slice in the original target space, and restore the flattened output without model-specific processor logic.

## Upstream reference fixtures and pretrained validation

- [`generate.py`](../../../test/models/timesfm3/reference/generate.py#L290) refuses any Google checkout other than commit `e31dadd84cb26bd5153fde6687502b8312e918fb`, assigns deterministic synthetic weights by sorted state-dict key, runs the pinned implementation, and writes [`golden.json`](../../../test/models/timesfm3/reference/golden.json). Regenerate it with `python test/models/timesfm3/reference/generate.py /path/to/timesfm`.
- [`test_public_model_matches_pinned_upstream`](../../../test/models/timesfm3/test_model.py#L508) validates the SDM public adapter with multiple targets, past-only and future-known covariates, missing values, variate attention, three quantiles, and non-aligned context and horizon lengths. The [internal upstream comparisons](../../../test/models/timesfm3/test_model.py#L736) additionally cover full-sequence CPM behavior and both decoding extraction modes. Normal tests consume the checked-in JSON and do not import Google code.
- The licensed checkpoint at Hugging Face revision `43046b85ec22d584a13f8098c2ed39c889e129c2` was manually smoke-tested on an NVIDIA L4 through the public `sdm.models.TimesFM3` API. Strict loading materialized all 330,710,976 parameters and rematerialized 20 non-persistent buffers on `cuda:0`; a two-target, three-step forecast returned 18 finite quantile columns, and one-shot and `fit`/`predict` outputs had maximum absolute difference `0.0`. This test is not part of CI because it downloads the 1.32 GB checkpoint under Google's non-commercial license.

## Internal full-sequence model

- [`_TimesFM3`](model.py#L368) preserves Google's module names and state-dict keys for the pre-transformer residual block, transformer stack, and output head. Tiny-model state dictionaries contain the same 49 keys, and loading identical weights produces exact CPU and CUDA intermediates and final logits, including through CPM refinement.
- The private forward boundary accepts `values`, `masks`, and `patch_is_target` as typed tensor arguments instead of Google's one-entry `inputs` dictionary. Output keys remain aligned because decoding and differential diagnostics consume the logits, RevIN statistics, and optional intermediates.
- Model construction accepts `device` and `dtype`, initializes the residual block's input dimension before checkpoint loading, and casts residual-block inputs directly to parameter dtype. This supports BF16 and meta-device construction without an avoidable full float32 concatenation.
- Leading fully masked patches use boolean `cummin` instead of Google's `int().cumprod().bool()`. The formulations are identical, while the boolean form avoids integer and boolean temporaries.
- Google's `PyTorchModelHubMixin` and `save_pretrained` method are not ported; SDM centralizes checkpoint download and loading in its model infrastructure.

## Decoding

- [`_TimesFM3.decode`](model.py#L713) preserves Google's single-pass context padding, covariate ordering, horizon inference, optional linear detrending, CPM refinement, frozen-statistics behavior, and stitched or non-stitched forecast extraction.
- Decode calls the SDM tensor-argument forward boundary directly instead of constructing Google's one-entry input dictionary. It remains inference-only through `torch.no_grad()` and returns auxiliary full-sequence outputs only when requested.
- Pinned golden tests cover both extraction modes, context and horizon padding, every covariate role, masks, horizon inference, detrending, CPM refinement, and frozen statistics on CPU and CUDA. Randomized differential probes across these branches produce exact outputs against the pinned implementation.
